# M10 리서치 — 공인회계사 2차 세법 Opus A/B 평가 설계

> 작성: 2026-08-01 · 접근일: 2026-08-01 · 소비 계획:
> `plans/2026-08-01-m10-cpa2-tax-codex-claude-ab.md`

## 질문

기존 M1~M9의 증거 위에, 실제 공인회계사 2차 세법 문제를 Codex와 Claude Opus가 각각 풀 때
law-mcp 사용 세션이 기능적 완성 판정선을 넘는가. 각 모델의 미사용 세션과 비교한 차이를 도구 기여로
해석할 수 있는가.

## 문제 선택

- 최신 회차인 **2026년도 제61회 공인회계사 제2차시험 세법의 첫 번째 대문제**를 고정 후보로 한다.
- 금융위원회는 제2차시험을 2026-06-27~28에 실시한다고 공고했다.
  - 시험 시행 공고: https://www.fsc.go.kr/po040200/87049
  - 시험 범위 사전예고: https://www.fsc.go.kr/po040200/84456
  - 시행계획 공고: https://www.fsc.go.kr/po040200/85723
- 실행 step-1에서 실제 문제 파일의 출처·SHA-256·페이지를 동결한다. 공식 원문을 우선하고, 공식
  내려받기 경로를 확보하지 못하면 동일 원문을 제공하는 신뢰 가능한 미러를 쓰되 두 사본의 페이지와
  해시 또는 시각적 일치를 대조한다.
- 세법 문제만 사용한다. 재무회계·원가관리회계 등 K-IFRS/회계 문제는 이 레포 범위 밖이다.

## 정답 기준의 한계와 보완

공식 모범답안이 없는 경우 단일 학원 해설을 정답으로 간주하면 판정이 해설자의 선택에 종속된다.
따라서 실행 전에 서로 독립적인 공개 해설 2종을 확보하고, 다음 순서로 채점표를 고정한다.

1. 문제의 명시 배점을 소문항 단위로 보존한다.
2. 두 해설의 기관·저자·발행일·원출처를 기록하고, 같은 저자·교재·정답 자료에서 파생되지 않은
   독립 출처임을 확인한다. 독립성이 확인되지 않으면 2종으로 세지 않는다.
3. 두 독립 해설이 일치하는 결론·계산·법적 근거를 잠정 정답으로 둔다.
4. 불일치는 시험 기준일에 유효한 법령·시행령·조세특례 규정으로 재판정한다.
5. 그래도 해소되지 않은 배점은 `분쟁`으로 표시해 분모에서 제외한다.
6. 확정 분모가 원문 배점의 70% 미만이면 전체 판정은 `평가 못 함`이다.

정답표는 solver에게 공개하지 않고 두 답안이 모두 동결된 뒤 채점자에게만 연다.

## 2×2 격리 계약

| arm | 모델 | MCP | 세션 |
|---|---|---|---|
| C+ | Codex `gpt-5.6-sol` | law-mcp만 | 신규·비지속 |
| C- | Codex `gpt-5.6-sol` | 없음 | 신규·비지속 |
| O+ | Claude `opus` | law-mcp만 | 신규·비지속 |
| O- | Claude `opus` | 없음 | 신규·비지속 |

네 arm 모두 동일 문제·답안 형식, 웹·Chrome·파일·셸·스킬·해설·레포 접근 금지를 공유한다. prompt는
모델별 형식 차이를 두지 않고 도구 사용 가능 여부 한 문장만 `+/-`에 따라 바꾼다.

Claude Code 2.1.220의 `--strict-mcp-config`, `--mcp-config`, `--tools ""`, `--no-chrome`,
`--disable-slash-commands`, `--no-session-persistence`, `--output-format json`을 사용한다. 두 실행은 레포
밖의 빈 임시 디렉터리에서 시작한다. A는 비시험 연막질의로 law-mcp 실제 호출 성공을, B는 같은
도구가 목록에 없고 호출 불가능함을 먼저 입증한다. 실제 답안 실행에서는 연막질의 세션을 재사용하지
않는다. 여기서 `--tools ""`는 CLI 도움말상 **내장 도구 집합**을 비우는 옵션으로 해석하되, 그 해석을
문서만 믿지 않는다. step-2에서 A의 MCP 도구 목록·실호출 성공과 B의 도구 목록 0을 동시에 관측해야만
본 실행으로 진행한다. A의 exact MCP allow-list는 로드된 도구 목록에서 생성해 manifest에 동결한다.

## 판정선

절대 판정은 C+와 O+ 각각에 적용한다.

- 확정 배점 총점 **80% 이상**
- 법적 처리 방향 배점 **90% 이상**
- 채점표가 요구한 핵심 법적 명제의 근거 제시율 **100%**
- 존재하지 않거나 틀린 조문·귀속시기 오류 **0건**
- 근거 없이 단정한 핵심 결론 **0건**

채점표는 소문항의 각 점수 단위를 `결론`, `계산`, `근거 존재`, `근거 정확`, `귀속시기 정합`의 이진
필드와 배점으로 쪼갠다. 오류는 `허위 조문`, `다른 조문`, `귀속시기`, `계산`, `논리 비약`, `문제
누락`으로 고정 분류한다. “법적 처리 방향”과 “핵심 명제” 목록도 답안 실행 전에 채점표에 명시해,
채점자가 답안을 보고 핵심 여부를 새로 정하지 못하게 한다.

C-와 O-는 합격 문턱이 아니라 각 모델의 대조군이다. C+/C-, O+/O- 차이를 따로 기록한다. C+와 O+
모두 통과하면 `강한 통과`, 하나만 통과하면 `혼합`, 둘 다 미달이면 `미달`이다. 단일 문제는 M1~M9
위에 얹는 종합시험이지 세법 전체를 단독 대표하는 표본은 아니다.

## 예상 실패와 중단 규칙

- A가 실제 배포 사본이 아닌 다른 law-mcp를 사용함 → 실행 무효, 배포 사본 일치 후 재실행.
- B에 사용자/프로젝트 MCP가 섞임 → 실행 무효, 빈 strict config로 다시 격리.
- 웹·해설·레포 접근 흔적 → 해당 arm 무효.
- 두 arm의 실제 모델 ID가 다름 또는 Opus가 아님 → 비교 무효.
- 출력 잘림·문제 본문 누락 → 해당 arm을 새 세션에서 동일 입력으로 1회 재실행하고 사유 기록.
- 확정 정답 분모가 70% 미만 → `평가 못 함`; 임의 해석으로 분모를 채우지 않음.

## 결론

이 설계는 “MCP를 쓰면 더 잘 푸는가”와 “현재 MCP가 실전 문제를 충분히 정확하게 풀게 하는가”를
분리한다. 전자는 A-B 차이, 후자는 A의 절대 판정선으로 답한다. 최종 `세법 기능적으로 충분` 선언은
판정 보고서를 본 사용자가 한다.
