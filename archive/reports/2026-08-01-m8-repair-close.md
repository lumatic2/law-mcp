# M8 · 문항 결함 수리 + 도구 실력 재측정 — 완료 노트

## 1. 결과

- **도구의 세법 전반 실력 추정치가 나왔다** — 확장 dev 40건 `pass^3` **75.0% → 90.0%** ·
  pass@3 90% → **100%** · SR@1 61.7% → 67.5%. 수리 8건 전부 3/3 으로 전환.
  `pass@3 = 100%` 의 뜻: 40건 전부 3회 중 최소 1회는 정답 조문에 닿았다 — 남은 격차는
  *도달 가능성*이 아니라 **일관성**이다.
- **수리가 정답을 바꾸지 않았음이 기계로 증명됐다** — `context`·`query` 제외 전 필드 diff **0건**,
  미수리 **176 레코드** 해시 변경 0건(계획이 요구한 144건의 상위집합).
- 후보 T 소진. 잔여를 후보 V(갱신)·W·X·Y 로 적재했다.

## 2. 이슈와 해결

- **계획의 근거가 틀린 것을 승인 전 검증자가 잡았다.** D1 은 "라벨을 고치려면 가드가 digest 로
  차단한다"고 적었는데 사실이 아니다. 실측: 승인 목록 **밖** 조문(`관세법 제1조`)은 exit 1 차단,
  목록 **안** 다른 조문(`종합부동산세법 제8조`)은 **exit 0 통과**. 라벨 보호는 전 필드 diff 대조가
  유일하다. 양방향을 다 밟아 기록했다 — 가드가 지켜 준다고 착각하면 다음 사람이 대조를 생략한다.
- **+15%p 를 전부 수리 효과로 읽으면 안 된다.** 질문을 건드리지 않은 32건 중 **4건이 함께 움직였다**
  (exp-39 +1 / exp-42·43·48 −3). 분해하면 수리 효과 **+20%p**, 회차 변동 **−5%p** 다. 부수 소득:
  문항 고정 상태 변동률 **12.5%** = `pass^3` 노이즈 ±5~7%p — M9 손실축 판정의 기준 폭이 생겼다.
- **새 사용자 결정이 실행 중에 생겼다(설계 실패로 계수 — ledger interruption 기록).** exp-42·48 이
  M7 에서 3/3 이라 전수 스캔에 안 걸렸는데 M8 에서 1/3 로 떨어졌다. **M7 의 통과가 운이었다는
  뜻**이고 처분(수리/제외/유지)은 사용자 소유다. **고치지 않았다** — 승인된 수리 pass 는 한 번이고
  이미 썼다. 점수를 본 뒤 또 고치면 2차 오염이다(후보 X).
- **드리프트 점검**: 계획 대비 확장·누락 없음. 해시 불변 범위만 144→176 으로 더 세게 걸었다(DoD 강화).
- **순조로움 재검증**: "수리 8건이 전부 3/3" 이 가장 무마찰한 구간이라 "문항이 쉬워진 것 아닌가"를
  되짚었다. 반증 근거 — ① 유출 검사 2종 + D7 금지어 전부 PASS(표제 용어·법령명 어간·약칭 미노출)
  ② **AT 가 1.28 → 1.35 로 올랐다.** 답을 알려 줬다면 재질의가 줄어 AT 가 내려가야 한다. 즉
  쉬워진 게 아니라 **모호성이 걷혀 재질의가 정답으로 수렴**했다.
- 별건 발견(수리 안 함, 후보 W): `leak-detect` 가 법령명 **어간**만 보므로 약칭이 통과한다 —
  `부가세`·`지방세`·`종부세`·`국제조세조정`. 해당 문항은 정답 법령을 사실상 알려 주므로 측정이
  실제보다 쉬워진다. 승인 범위(변별 결함 3유형) 밖이라 기록만 했다.
- 크기 회고: 독립 step 2개(데이터 수리 / 블라인드 재측정) + 통합 검증(전/후 비교 + 라벨 불변 증명)
  으로 milestone 규모 정합. changeset 1개로 닫히지 않았다.
