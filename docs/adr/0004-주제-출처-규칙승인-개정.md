# ADR 0004 — 주제 출처: 승인된 결정적 규칙을 동급 출처로 추가 (ADR 0002 §2 개정)

- Status: Accepted (2026-08-01)
- Milestone: M5 step-2 (목표 `tax-corpus-breadth`)
- 개정 대상: [ADR 0002 — 평가 문제 봉인 규약](0002-평가-문제-봉인-규약.md) §2. **폐기가 아니라
  출처 계층 추가**다. ADR 0002 의 Context·Decision §1·§3·§4 는 그대로 유효하다.

## Context

측정이 주요 6법(소득·법인·부가·국기·조특·상증) 위에서만 서 있다는 편중이 실측됐다 —
코퍼스 `expected_laws` 분포에서 그 밖의 세법은 **0건**이고, 넓이판 리허설 7건(종부세·지방세·
국세징수·조세범처벌·국조법 등)은 전건 도달했지만 지표로는 남지 않았다
(`evidence/2026-07-31-m4-rehearsal-breadth.md`). 그래서 사용자가 코퍼스를 세법 전반으로 넓히기로
결정했다(2026-07-31 결정 ⓓ).

문제는 ADR 0002 §2 다: **"주제는 사람이 정하거나 이미 있는 라벨에서 온다. 에이전트가 주제를
고르지 않는다."** 이걸 `bench/check-no-new-topics.ts` 가 기계로 강제한다 — 코퍼스의 모든 정답
조문이 통합 전 세트에 이미 있었음을 검증한다. 새 세법 조문은 정의상 통합 전 세트에 없으므로
**개정 없이는 확장 자체가 차단**된다.

두 갈래뿐이었다: ① 사용자가 60개 주제를 직접 고른다(원문에 가장 충실하나 사용자 노동이 크다)
② 규약을 개정한다. 사용자는 ②를 골랐고, 그 방식으로 **"추출 규칙을 승인"**을 택했다.

## Decision

**"사람이 승인한 결정적 규칙"을 사람과 동급의 주제 출처로 인정한다.** 에이전트의 개별 취향
선정은 계속 금지다 — 바뀐 것은 사람이 *주제 하나하나*를 고르는 대신 *선정 규칙*을 고른다는 점뿐이다.

1. **규칙은 파일이 정본이고 코드가 아니다.** `bench/expansion/rules.approved.json` 에 키워드·
   할당량·간격 방식·중복 정책·봉인 배정식이 들어 있고, 추출기(`bench/expand-topics.ts`)는 그
   파일만 읽는다. 규칙을 코드에 심으면 그건 승인된 규칙이 아니라 코드를 쓴 에이전트의 취향이다.
2. **가드 예외는 파일의 *유무*가 아니라 *digest* 로 검증한다.** `check-no-new-topics.ts` 는
   승인 목록(`topics-*.json`)에 있는 조문을 통과시키되, 그 목록의 `rules_digest`(규칙 파일 해시)와
   `list_digest`(주제 목록 해시)를 재계산해 일치할 때만 인정한다. 목록에 손으로 한 줄을 추가하면
   digest 가 어긋나 차단된다 — 예외 경로가 "무조건 통과"로 변질되지 않게 하는 유일한 장치다.
3. **ADR 0001 위임 재라벨은 예외에 포함된다.** 승인 목록의 조문을 읽어 보니 실체가 시행령에
   있어 라벨이 시행령으로 옮겨간 건은, 승인 목록에 그 시행령 조문이 없더라도 `label_rule` 표시로
   통과시킨다(ADR 0002 §2 가 이미 둔 예외와 같은 성격). 조문식별자 표기 차이(`51-4` ↔ `제51조의4`)는
   정규화해 비교한다.
4. **결정성의 주장 범위를 좁혀 적는다.** "동일 규칙 파일 + 동일 MST 에서 재현"이다. 상류(법제처)
   개정으로 조문이 바뀌면 재현이 깨진다 — 이 한계를 선정 로그에 기록하고 숨기지 않는다.

### 봉인 누출 경로와 방어 수준 (ADR 0002 §1·§4 의 실행 조건)

봉인분 20건도 산문은 에이전트가 쓴다(누군가는 써야 한다). 그래서 봉인의 보장은 "아무도 본 적
없음"이 아니라 **"튜닝·측정에 쓰지 않았음"**이다. ADR 0002 의 문구보다 약한 보장이므로 경로별로
무엇이 장치이고 무엇이 규율인지 명시한다:

| 누출 경로 | 방어 | 수준 |
|---|---|---|
| 측정 러너로 `sealed` 를 채점 | 플래그 없는 `sealed` 접근 거절 + 개봉 이력 append 요구 | **장치** (M6 step-4) |
| `bench/corpus.json` 에 dev 와 평문 공존 | 없음 — 파일을 열면 보인다 | 규율 |
| 라벨 검증 기록 열람 | sealed 분을 별 파일로 분리 + 머리에 "튜닝 중 열람 금지 · 열람 시 ledger 기록" 고지 | 규율 + 표식 |

"장치가 다 막는다"고 적지 않는 이유는 ADR 0002 §4 와 같다 — **놀고 있는 장치를 다음 사람이
신뢰하는 것**이 아무 장치도 없는 것보다 나쁘다.

## Consequences

- 확장 60건이 규약을 우회하지 않고 근거를 남기며 가드를 통과한다. 가드는 삭제되지 않고, 승인
  목록 밖 주제에 대해서는 **여전히 차단**한다.
- 다음에 또 주제를 늘릴 때는 새 규칙 파일을 만들어 사용자 승인을 받고 digest 를 갱신해야 한다.
  규칙 없이 목록만 늘리는 경로는 없다.
- ADR 0002 §2 의 "에이전트가 주제를 고르지 않는다"는 살아 있다. 이 ADR 이 바꾼 것은 사람의
  개입 지점이 *주제 60개*에서 *규칙 1개*로 올라간 것이고, 그 대가로 **규칙 설계 자체가 에이전트
  손에 있다는 잔여 위험**을 진다. 완화 장치는 ①규칙의 파일화(감사 가능) ②선정 로그(법별 매칭수·
  간격·중복 대체 전량 기록) ③digest 고정이다. 이 잔여 위험은 없앤 것이 아니라 **드러낸 것**이다.

## Alternatives considered

- **사용자가 60개 주제를 직접 고른다** — ADR 0002 §2 원문에 가장 충실하다. 사용자가 규칙 승인
  방식을 명시 선택해서 채택하지 않았다(2026-07-31).
- **가드를 삭제한다** — 확장은 즉시 통과하지만 다음 오염을 아무도 못 잡는다. ADR 0002 가 이
  가드를 만든 이유(구성에 의한 오염은 유출 탐지기로 안 잡힌다)가 그대로 유효하다.
- **가드 예외를 "파일이 있으면 통과"로 둔다** — 목록에 손으로 한 줄 추가하는 것을 못 막아
  가드가 사실상 죽는다. fresh 검증자가 지적한 구멍이고, 그래서 digest 검증을 넣었다.
